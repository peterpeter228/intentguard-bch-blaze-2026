WizardConnect and relinking

The browser payment bundle statically includes @wizardconnect/core and @wizardconnect/dapp. Their installed source headers identify Copyright (C) 2026 Whiterun LLC and the GNU LGPL version 3.0 or later. @wizardconnect/react is also an installed dependency and is included in the separate browser probe. The upstream WizardConnect source repository contains the library source; the linked evidence records the exact package revisions.

When distributing a statically linked combined work, LGPLv3 section 4 requires recipients to be able to modify the library and recombine or relink the work, using the required corresponding library source and suitable application material, or another option permitted by that section. Preserve the applicable notices and permit reverse engineering for debugging modifications as required by the license.

The MIT-licensed application source is published at peterpeter228/intentguard-bch-blaze-2026. The following source substitution was verified for LGPLv3 section 4(d)(0) recombination of both payment bundles:

  1. With Node 24, make an isolated application copy and run npm ci --ignore-scripts --no-audit --no-fund in it.
  2. In separate copies of the WizardConnect source repository, check out core gitHead ca2b02f14ccfa2e367625c5f9291c62fb34f4a59 and dapp gitHead 201e234bef057751a333e70c5618d626be27ed2c. Make the desired library changes there and make the isolated application's node_modules available to each source copy.
  3. For core compilation, install nostr-tools@2.23.1 from the core source's lockfile into its packages/core/node_modules; the application keeps its locked nostr-tools@2.25.2. Compile packages/core/tsconfig.json with the application's TypeScript compiler and replace the isolated application's node_modules/@wizardconnect/core/dist with the resulting packages/core/dist. Then compile and replace packages/dapp/dist in the same way, against the substituted core.
  4. Run npm run build:production in the isolated application copy. The recombined files are dist/production/public/visitor-payment.js and dist/production/legacy-payment.js.

The local check used non-functional comments and checked the resulting module syntax and bundle contents; it did not establish wallet or runtime compatibility for arbitrary modifications. Native dependencies may need their normal rebuild before running the application.
