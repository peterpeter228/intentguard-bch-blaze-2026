# 路演、演示、提交与评审期维护

本章是开发后的材料规格与可填写草稿。所有 `<待填>` 必须用实际证据替换；实现前不能把功能陈述当成已验证宣传。XO个人体验反馈不在本章生成。

## 1. 一句话定位

中文：**给 BCH dApp 的支付意图检查器：逐项核对收款人、资产、金额、找零和费用，再由用户钱包签名。**

英文候选：**A transaction-intent checker for BCH apps. Check the recipient, asset, amount, change, and fee before the user signs.**

品牌暂名 IntentGuard BCH，不使用“Official”“审计认证”“100%防骗”“原子跨链”或“保证退款”。若未做真正XO实现，不在产品名加XO；不把未实现的x402或Avalanche放在首屏吸引点击。

## 3. 两分钟演示脚本

| 时间 | 演示动作 | 说明要点 |
| --- | --- | --- |
| 0–15秒 | 打开真实首页 | “开发者能在钱包签名前核对真实交易是否符合用户确认的付款请求。” |
| 15–40秒 | 载入1 PUSD请求，切换收款被替换fixture | 明确这是受控测试；显示原收款script与实际输出差异，签名入口被阻止 |
| 40–55秒 | 切换假同名币或异常找零fixture | 只选最直观的第二例，说明检查资产identity与资金去向 |
| 55–85秒 | 正常交易预检与钱包签名 | 看真实金额/费用、用户签名、真实txid；链确认未完成就显示待确认 |
| 85–105秒 | 打开真实收据并重查 | txid、vout、资产数量、确认状态、源码/部署版本可追溯 |
| 105–120秒 | 打开独立开发者示例与下一步 | 同一个guard可在另一UI调用，说明一条真实反馈或尚待验证的集成假设 |

录屏时若不适合等待确认，可清楚切到此前已完成的真实受控主网收据，标示交易时间；不能剪辑成同一笔即时确认。视频不能替代当前在线demo。评委不应被要求为看产品价值先充值、创建账户或付一次“AI审计费”。

XO补充演示最多60–90秒，单独说明Template、Invitation、Debug Tool、真实交易和适用的后续动作。未实现则不拍模拟片冒充完成。

## 5. 针对主办方的必要确认问题

仅准备问题，未在本轮发送；未来发送以用户授权为准。每次围绕一个阻塞，附最小背景，避免大量泛泛询问。

- 平台widget与官网截止差一小时，最终生效的截止UTC时刻是什么？注册是否有具体小时？
- 对真正的旧项目，同repo固定旧tag+新分支/commit+赛前demo是否满足旧/新repo披露，还是需要分别可访问的仓库入口？
- 当前XO Debug Tool官方入口、样例commit与schema版本是什么？本项目的非托管付款请求与独立预检是否适合Build，现有EVM功能迁移怎样证明相关性？
- 无自然follow-up的用例，如何记录不适用性？不要把问题写成官方已强制要求。
- bounty权利放弃条款对预先存在代码、参赛新增模块和第三方开源依赖各适用什么范围？
- 中国个人如获奖，具体领奖身份、收款和其他条件有哪些？公开全球资格不能替代这些细节。

不要请求主办方保证获奖，不以评委私人身份推断偏好，不为社区票自造用户或伪造互动。真实技术反馈和可用作品更适合公开展示。

## 6. 评审期运行

从提交到11月28日结果公布，至少保持官网、演示、源码和收据入口可用。记录外部服务故障并提供清晰降级提示；发生必须修复的缺陷时，先核对允许修改的规则，保留提交版本与变更日志。

用户反馈、社区投票与评审得分分别记录。不要把访问量当钱包用户、把自付交易当GMV、把赞助方一次答复当合作承诺。结果无论获奖与否，保存真实开发记录，供后续集成与Team1提案使用。
