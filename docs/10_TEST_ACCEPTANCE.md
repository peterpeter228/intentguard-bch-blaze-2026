# 测试、真实钱包验收与证据规格

## 1. 测试层级和诚实标记

| 层级 | 证明什么 | 不能证明什么 |
| --- | --- | --- |
| 类型/构建/依赖 | 代码与锁定SDK可以共同编译 | 钱包实际支持、主网可用 |
| 纯数据单测 | 解析、金额、guard规则和状态推导 | 网关可靠性、真实签名能力 |
| Mock adapter集成 | 错误与重试流程、并发与状态恢复 | 真实钱包/链交易已通过 |
| Chipnet | 测试链、可用钱包、具体交易执行 | BCH主网资格与真实PUSD价值 |
| 受控主网实测 | 指定版本与环境下能执行实际付款 | 全钱包兼容、真实客户、商业采用量 |
| 独立浏览器与第三方复核 | 可访问、可理解、可重新查证 | 资金合约已获审计或未来零风险 |

所有命令以实际package.json为准，不假设每个仓库都有`yarn test`。G0创建必要scripts后记录准确命令。不要关闭真实交易验证来使mock通过，也不要用浏览器假钱包标签冒充设备测试。[S09]

## 2. P0关键测试矩阵

| ID | 场景/输入 | 必须观察到的结果 |
| --- | --- | --- |
| A01 | PUSD `0.01`、`1`、`1.10` | 基础单位分别1、100、110；显示来回一致 |
| A02 | `0`、负值、`1e2`、`NaN`、`1.001`、超协议上限 | 拒绝支付输入，不四舍五入 |
| A03 | BigInt大于JS安全整数的序列化 | 全程保持十进制字符串与精确整数 |
| A04 | 主网/Chipnet地址错配、checksum错 | 构建前拦截；不给钱包签名 |
| A05 | 有效token-aware P2SH | 若MVP不支持则明确UNSUPPORTED；不得说地址本身无效 |
| A06 | 同symbol/icon但category不同 | 不认作PUSD，不按显示名付款 |
| A07 | 模型提取错金额、换地址、含指令文本 | 只是未确认草稿；不改变资金规则、不执行指令 |
| G01 | 收款脚本被替换 | `RECIPIENT_MISMATCH`，签名函数未被调用 |
| G02 | 正确收款但多一个外部输出 | `UNAPPROVED_OUTPUT` |
| G03 | 目标币少付/超付、把FT改为另一category | 金额/资产错误，不放行 |
| G04 | BCH/token找零改为第三方地址 | `CHANGE_NOT_OWNED` |
| G05 | PUSD对，费用或BCH承载资金异常增大 | 超预算拦截；不是只看token数量 |
| G06 | 输入包含NFT/minting/mutable能力 | P0排除/不支持，NFT不能被丢弃 |
| G07 | 输入含非目标category，或该资产被烧毁/转给未批准收款方 | P0因非目标资产输入或未批准流出拒绝；数量减少时另报Token守恒失败 |
| G08 | 调用方伪造prevout satoshis/token | 与真实原交易不符时拒绝；无数据为UNKNOWN |
| G09 | 相同outpoint重复作为输入 | `DUPLICATE_INPUT` |
| G10 | 相同地址字符串不同表现但同脚本 | 规范化按脚本判断，不只比较缩写文本 |
| G11 | 智能合约或未知锁定脚本 | 不支持的路径不能绿色放行 |
| G12 | 意图已过期、候选同时改动意图对象 | 过期拒绝；冻结hash和原对象不被覆盖 |
| G13 | 多个合法UTXO聚合/无token找零/有找零 | 精确守恒、正确fee/承载额、报告明确 |
| G14 | 选择后某UTXO被其他程序花费 | 重取后重建并重检；不得沿用旧“通过”标记 |
| W01 | 连接、断开、刷新与重新配对 | 没有串到旧会话/错误路径；状态可解释 |
| W02 | inputPaths乱序、路径没被钱包提供 | 阻止签名或收到明确拒绝；不能任意猜路径 |
| W03 | 用户拒签/取消/超时 | UI可恢复；未广播不能显示已付款 |
| W04 | 钱包返回已签hex，输出/费用/locktime被改 | 签名后复核失败，不广播 |
| W05 | 钱包自动广播或不尊重broadcast:false | 能力表记录真实行为；不可宣称具备广播前二次阻止 |
| W06 | 连续点击、两标签页同时付款 | 同操作只产生一次活跃签名/付款；其他请求提示在途 |
| W07 | 取消/修改意图/重连后旧签名迟到 | attempt/session/sequence/revision不匹配则丢弃自动广播路径，保持可核对记录 |
| W08 | 未拿到signed hex时签名响应超时 | 不编造txid；按输入/钱包/链历史调查，状态未知不当付款成功 |
| R01 | 广播响应丢失但链上已见 | 查询原txid恢复成功，不生成第二笔付款 |
| R02 | 已签但未广播 | 仍显示已签状态，不能直接生成已付款收据 |
| R03 | 假txid、错误网络、少付或错误商户 | 收据验证失败，保留具体原因 |
| R04 | 同(txid,vout)用于两个订单/重复verify并发 | 同订单幂等返回；不同订单不能重复分配权益 |
| R05 | 刷新、服务重启、断网重连 | 从原operationId与链事实恢复，不能重置为可再付 |
| R06 | 确认后重组或输入冲突 | 降级确认状态；保存观测时点与blockHash变化 |
| R07 | 只用公开txid抢领别人私有服务 | 若做服务权益则阻止；P0只展示公开付款事实 |
| R08 | 已付款后receipt接口暂时失败 | 可重查并重建同一收据，无需再付款 |

测试要验证“签名/广播是否实际被调用”，不只断言页面出现红字。至少一部分恶意候选由独立测试逻辑修改真实交易结构，避免guard与builder复用同一错误而自证正确。

## 3. 真实钱包与设备矩阵

初始状态全部为 `NOT_RUN`。记录确切版本；网页说支持某协议不能直接勾为通过。

| 组合 | 必测内容 | P0状态要求 |
| --- | --- | --- |
| 选定首个钱包 + 桌面浏览器 | 配对、路径、纯签名、正常支付、拒签、恢复 | 至少一组完整通过 |
| 第二个钱包 + 同浏览器 | 同上，特别broadcast差异 | 未测就不宣传兼容；P1目标 |
| 手机钱包 + 桌面二维码 | 扫码、切后台、返回、断线恢复 | 作为宣传支持组合时必须通过 |
| 手机浏览器 + 手机钱包 | 深链/返回、重连、按钮和二维码可见 | 若没实现深链，明确只支持已测扫码路径 |
| 1366×768、390×844视口 | 金额/地址/风险文字不截断，按钮能操作 | 两种视口均检查 |

记录模板：设备/OS/browser/wallet版本、网络、SDKlockfile hash、commit、开始/结束时间、步骤、实际结果、录屏/截图路径、txid（如有）、是否用户签名、失败是否可重现。不得把完整钱包session或密钥放入证据。

## 4. 主网实测计划

dot先提供一个具体交易计划：付款资产、金额、发送/接收钱包归属、目标地址、网络、BCH承载资金、费用上限、可能损失上限、失败恢复步骤。金额取实际足够完成测试且用户已授权的小额；本包不预授权任何付款。

推荐采用两个用户控制的钱包进行受控演示，区分付款方与收款方；不必假装外部客户。先Chipnet验证，再按实际支持将主网BCH/PUSD测试分开。若代币获取需换币或最小金额，先报告实际成本；不假定0.01 PUSD即可覆盖所有手续。

完成后必须保留：

1. 对应commit与部署URL。
2. 已确认PaymentIntent、guard报告及候选承诺（脱敏）。
3. 64位txid、network、正确vout、输出script、category、amount。
4. 独立取得的原交易/prevout事实，确认数、区块哈希、核验时间。
5. 钱包UI中用户签名与页面正确状态的演示证据；不记录敏感输入。
6. 收据链接及第二次独立重查结果。

同一受控钱包之间的转账可以证明功能，不能计作真实客户数、销售额或产品收入。若只拿到mempool观察，写“已广播/待确认”，不写“最终结算”。

## 5. 浏览器验收脚本

无需钱包的评委路径：匿名打开首页 → 运行安全fixture → 换四个恶意fixture → 展开差异 → 打开真实收据 → 查看开发者例子与源码 → 所有外链匿名可读。

需要钱包的支付路径：从请求页面开始 → 查看完整金额与收款地址 → 连接 → 检查通过 → 钱包拒签一次 → 返回可重试状态 → 重新确认 → 完成实际签名与广播 → 收据 → 刷新重查。

失败恢复路径：在签名前断网、广播响应超时、链端返回错误分别模拟。模拟网络事件可以证明UI分支，真实广播与钱包另有证据，二者不混称。浏览器日志不能出现未处理异常；长地址/报错不能撑破手机宽度。

## 6. XO与桥的额外验收

XO按第06章归档schema校验、Debug Tool、真正使用的Invitation、真实交易和重现方法；follow-up仅对实际底层结构适用时验证。人类反馈另外登记，不由代码测试代替。

桥按第07章的双向、部分完成、用户中间资产、服务商风控/退款、恢复与最终到账验收。没有真实双向链证据，不能把链接到第三方网站当已完成桥赏金。

## 7. 发布准入与停止验证

以下阻止发布为“已完成”：错付候选被放行、未验证的地址替换、NFT意外花费、签名后变更未发现、未知广播结果导致重复付款、假已付状态、秘密泄漏、实际资格缺口未披露。

排版微调或已明确不支持的钱包不是无限扩测理由。关键风险验证完成、真实主线通过后，停止添加无关测试，进入演示与提交。最后由独立审查者针对冻结commit复核重要风险；新修复影响哪条路径就补哪条验证。

`evidence/validation/summary.md` 必须分开列 PASS / FAIL / NOT_RUN / NOT_APPLICABLE。任务完成时间、命令退出0或CI绿色不能替代这个分类。
