# 任务分解与执行顺序

以下工时为单人配合 dot 的**主动工作估算**，不含确认区块、外部答复、审批或钱包配置等待，不构成交付保证。能复用旧项目才减少相应任务；缺少实际旧项目不得声称“只需增量改几行”。

状态枚举：`TODO`、`IN_PROGRESS`、`BLOCKED_EXTERNAL`、`DONE`、`NOT_APPLICABLE`。每项 DONE 必须有证据、commit与验证时间。本交接包中所有实现任务均为 TODO。

## G0：资格、基线和兼容性（赛前可做，约5–9小时）

| ID | 任务与依赖 | 具体交付 | 验收/退出条件 |
| --- | --- | --- | --- |
| T00 | 实际环境和仓库清点 | `evidence/setup/environment.md`、HEAD、可用工具、dirty状态 | 确实读到目标；未读到旧repo时不申报迁移 |
| T01 | 重查比赛与报名/点名任务 | 规则矩阵、日期、官方URL、人工事项 | 每个资格条件有Owner与证据缺口 |
| T02 | 基线与工作类型，依赖T00 | `baseline.md`、真实旧demo、tag或SHA、license | 赛前实现如实标记；不创建假历史 |
| T03 | 最小依赖实验，依赖T00 | registry实值、精确锁版本、安装/typecheck/build记录 | 不能用自定义类型蒙混通过；失败先修闭包 |
| T04 | 钱包协议可用性，依赖T03 | 仅官方Chipnet样例或已知交易非广播签名的能力表、取消证据 | G2前不以新业务代码做主网付款；真实返回值与broadcast行为明确 |
| T05 | XO只读/样例实验（可并行） | 工具URL、版本闭包、官方样例验证结果 | 限时2–4小时先证明可访问及schema；失败暂关XO |
| T06 | 产品问题验证（可并行） | 目标用户假设、替代方案、可发送访谈问题 | 未获得发信授权只准备问题；不编反馈 |

G0出口：知道做新项目还是旧项目增量；主网资格可达路径明确；SDK无已知安装冲突；至少一个钱包路线有可行证据。若点名资格已错过且无官方豁免，应明确不再承诺本届主赛道，但可继续独立开源项目。

## G1：核心规格与纯数据检查（赛期实质实现，约7–11小时）

| ID | 任务与依赖 | 具体交付 | 验收/退出条件 |
| --- | --- | --- | --- |
| T10 | 冻结PaymentIntent与支持范围，依赖T02–04 | 类型、schemaVersion、金额解析、资产registry | 字符串→bigint边界；主网/测试网隔离 |
| T11 | 真实交易解码与prevout验证，依赖T10 | chain adapter、输入证据结构、网络校验 | 假sourceOutputs、缺prevout不能PASS |
| T12 | guard核心，依赖T10–11 | 所有输出/资产/费率/找零检查与错误码 | 10章关键资金负例全部拒绝且正常例通过 |
| T13 | 恶意候选演示与独立调用例子，依赖T12 | 4个清楚标fixture的攻击例、一个外部调用样例 | 不只是UI标签变化；删除UI仍能调用并复现结果 |
| T14 | UI骨架与参赛banner（T10后可并行） | 真实路由、英文信息层级、可配置正式链接 | 不默认装旧slides或假地址，移动端不溢出 |

G1出口：用户意图不可被候选篡改；正常/异常交易结果有独立可复现证据。若guard仍信任调用方传入“真实收款地址”而不与冻结意图比较，不能进入实币签名。

## G2：钱包到收据的完整闭环（约9–15小时）

| ID | 任务与依赖 | 具体交付 | 验收/退出条件 |
| --- | --- | --- | --- |
| T20 | HD路径和UTXO选择，依赖T04/T11 | 范围明确的地址发现、多UTXO、纯FT筛选 | 找零归属、NFT不花费、余额不夸大 |
| T21 | 候选构建与费用，依赖T12/T20 | build adapter、确定费用/承载额、预检报告 | 所有输出进入Guard，未知脚本禁止放行 |
| T22 | 钱包签名与二次检查，依赖T21 | 实际inputPaths、取消超时、signed验证 | 改收款/数量/找零/费用的返回值不广播 |
| T23 | 广播/观察/恢复，依赖T22 | 状态机、txid计算、幂等、重查路径 | 超时但已上链不引发第二次经济付款 |
| T24 | 收据核验，依赖T23 | txid/vout/确认数/脚本/金额重查、导出 | 假txid、错网、重复认领、重组无假成功 |
| T25 | 正常和错误UI，依赖T14/T22–24 | 用户确认、拒签、失败恢复、receipt页 | 桌面和手机视口真实点击；无无限转圈 |
| T26 | Chipnet与主网测试，依赖T22–25 | 脱敏日志、真实钱包版本、原始证据索引 | Chipnet不等于主网；主网需已授权具体范围 |

若赛期第3天仍无钱包签名及广播可控证据，停止所有P1/P2并优先解决资金链路。G2出口：一条真实主网闭环完成，核心浏览器异常可恢复，所有成功状态由真实证据驱动。证据不足时所有次要赛道保持关闭。

## G3：XO与可选扩展（约4–12小时，是否实施由gate决定）

| ID | 任务与依赖 | 具体交付 | 验收/退出条件 |
| --- | --- | --- | --- |
| T30 | XO功能映射，依赖T05/G2 | 原需求→模板字段/链上规则映射、novelty说明 | 不把普通样例改名冒称新设计；不引入资金池 |
| T31 | XO模板与Invitation，依赖T30 | schema验证、Debug Tool导入、真实交易、重现流程 | 完整5/6项资格对齐；follow-up按实际适用性 |
| T32 | Migrate真实性，依赖T02/T31 | 原工作项目、功能差异、新旧链接 | 没有旧项目则NOT_APPLICABLE |
| T33 | XO原始日志，依赖T31 | 时间、版本、实际错误和重现 | 人类反馈未完成不能用AI文章填空 |
| T34 | 自愿退款请求（选做） | 请求与真实返款交易关联 | 非撤销、无保证；只在链上返款后标完成 |
| T35 | 桥可行性gate（选做，依赖G2） | 只读permissions/币种/双向quote/最小金额/条款 | 4–6小时仍未证明就关闭；Cauldron合约须独立固定策略验证，不放宽P0，不写HTLC补洞 |
| T36 | 桥端到端（仅T35通过） | 两跳状态、用户中间钱包、双方向实测 | 估算另需12–24小时；不能抢占冻结时间 |

XO/Migrate/Bridge 各自独立状态。XO成功不代表mainnet资格已完成；Chipnet XO符合其赏金某条要求，不自动满足主网赛道。

## G4：演示、材料与提交（约7–11小时）

| ID | 任务与依赖 | 具体交付 | 验收/退出条件 |
| --- | --- | --- | --- |
| T40 | 主线独立审查，依赖G2 | 精确commit评审、资金负例、已修复列表 | 无未解决的错误放行、重复付款或资格漏项 |
| T41 | 真实用户/开发者观察 | 实际完成率/问题、可用原话、集成反馈 | 自付演示和外部验证分开；不编商业证据 |
| T42 | 七页演示、两分钟视频 | 填写后的项目slides、可访问视频 | 链接匿名打开；全部声明有证据 |
| T43 | 清理与冻结 | secret/license检查、README、lockfile、reproduce、部署commit | 真实部署版本与测试证据相符 |
| T44 | 提交预检 | 规则矩阵全项、IP/地址/人类反馈核实、表单草稿 | 先给具体材料；只暂停尚缺的用户动作 |
| T45 | 正式提交/回执 | 实际提交URL、时间、参赛类别与回执 | 按已授权范围操作；无回执不能标提交成功 |
| T46 | 评审期可用性 | live服务状态、日志、反馈渠道 | 保持在线，冻结后重大改动遵守赛事规则 |

## 推荐赛期节奏（北京时间）

- **11/14 22:00–11/15：**最终核对规则，冻结真实赛前基线，完成G1核心。
- **11/16–11/17：**G2真实钱包与收据；先形成稳定可演示版本。
- **11/18–11/19：**修复实测问题；仅在P0稳定后加入最有证据的XO模块。
- **11/20：**停止新增跨链/Media功能；独立审查、准备路演。
- **11/21 18:00前：**冻结候选源码与部署，完整彩排；**22:00前完成内部目标提交**。
- **11/22：**留作已发现问题和平台故障缓冲，始终以再次核实的官方有效截止为准。

这是35–55小时左右核心主动工作的排期假设，技术新手、兼容性问题或外部审批可能增加时间。不要承诺8天一定做完五套产品。约束满足不了时按P2→P1→可选AI顺序删减，不能删去主网证据、独立guard和资格证明。
