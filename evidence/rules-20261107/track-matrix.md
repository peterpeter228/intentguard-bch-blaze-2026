## Development implications
1. Keep a truthful pre-event baseline now, reproducible tests and clear change log. Anything implemented before November 14 remains prior work; preserve before/after evidence instead of relabelling it.
2. Make the two-minute demo compelling and coherent: one ordinary payment safety problem, deliberate mismatch failures, obvious recipient/amount/network confirmation, minimal steps, honest distinction between simulation and real execution.
3. Add one genuinely novel functional XO template only after feasibility checking current stack. Prioritize real reproducible invitation evidence on Chipnet, normal debug-tool import and any applicable follow-up, rather than speculative multiple integrations.
4. Freeze human-only XO development feedback outside AI drafting. Preserve factual test artifacts for project QA, but do not supply feedback prose, phrasing, or “personal” experiences for the user to submit.
5. Plan current known eligibility gaps explicitly: live hosted demo and accessible source, mainnet sending feature/evidence, current invitation/template evidence, registration and Telegram confirmation. User-provided roll-call screenshot is already acknowledged below.
6. Do not introduce a cross-chain bridge or identity system just to add labels; each has substantial substantive requirements.
7. Any future bounty submission needs the user to review the unusually broad IP waiver. No waiver accepted or submission made here.
