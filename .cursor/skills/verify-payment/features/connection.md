# Connection
## Sub-features
Explicit BCH mainnet acknowledgement, transient pairing, fresh key exchange, receive/change path derivation, disconnect/cancel; legacy Chipnet private path separate.
## How to get to it (user POV)
Homepage → guarded visitor-wallet payment → BCH mainnet → acknowledge actual wallet network → Connect WizardConnect. Never capture pairing URI/QR.
## Driving it with HTTP/SDK harness
`npm run payment:verify -- NEW_DIRECTORY` uses actual pinned manager on the existing isolated Chipnet signing seam; visitor UI reuses those already-generated bytes verify-only with synthetic session/source callbacks. No mainnet signature is generated. Parent browser checks actual #network/#chain-ack/#connect/#wallet-state without opening/signing a real wallet.
## Gotchas
Stock-wallet session and wallet's adherence to sign-only are NOT_RUN. Cached pubkeys are not authentication; no authenticated chain ID exists in protocol. Drop/reconnect requires a new explicit handshake, not automatic re-sign.
